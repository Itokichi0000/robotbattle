### 手動・起動確認

- `OPERATOR_PASSWORD=... pnpm dev`：1プロセスで server + display/pilot/operator（Vite ミドルウェア）が同一オリジン :4400 で起動。
  `/display/` `/pilot/` `/operator/` 200、`/display` → `/display/` 302、`/` → `/pilot/` 302。
- `pnpm build && NODE_ENV=production ... node apps/server/dist/index.mjs`：CSP（`script-src 'self'`、eval なし）・HSTS 付きで
  3アプリともコンソールエラーなしで表示。HTML は `no-cache`、ハッシュ付き資産は `immutable`。
- 本番で `OPERATOR_PASSWORD`/`PUBLIC_BASE_URL` 不足、`APP_MODE=live` は起動拒否（メッセージを確認）。

### FPS（正直な記録）

| 条件（このコンテナ、SwiftShader） | 解像度    | 実測        |
| --------------------------------- | --------- | ----------- |
| SAFE（影なし・ブルームなし）      | 1920×1080 | 約 1〜5 FPS |
| BALANCED                          | 1920×1080 | 約 1〜5 FPS |
| CINEMATIC（MSAA×4・影・ブルーム） | 1920×1080 | 約 0.2 FPS  |

ソフトウェア描画のため GPU 環境の指標にならない。自動画質調整（FPS<28 が約9秒続くと1段下げる）がこの環境で
CINEMATIC→SAFE に下がることを運営画面の DISPLAY 欄で確認。**会場 GPU での 1920×1080/60fps 目標は未検証。**

### 負荷試験

`apps/server/scripts/loadtest.ts`：DEMO GUEST でログインした実ソケットのスマホが席に着き、デモ BOT と同じ判断で操作する（Cookie・ack・
レート制限を含む本物の経路）。大画面ソケットはスナップショットの頻度・間隔・サイズを記録。サーバーと負荷側が同じ 4 vCPU コンテナ
（本番より不利な条件）。

| 条件                                              | 送信 / ack / 喪失 | ack 往復 p50 / p95 / 最大 | 拒否の内訳                                                       | 大画面スナップショット                     |
| ------------------------------------------------- | ----------------- | ------------------------- | ---------------------------------------------------------------- | ------------------------------------------ |
| 8人着席 + 大画面3、60秒（通常の操作）             | 50 / 50 / 0       | 4 / 6 / 9 ms              | なし                                                             | 9.3 回/秒・間隔 p95 151 ms・4.6 KB（JSON） |
| 8人着席 + 大画面3、45秒、**全員 50ms ごとに連打** | 4,624 / 4,624 / 0 | 2 / 9 / 109 ms            | RATE_LIMITED 2,400・OVERDRIVE_NOT_READY 2,052・NOT_IN_COMBAT 134 | 9.1 回/秒（連打で増えない）                |
| 30台（8人着席 + 22台観戦）+ 大画面3、60秒         | 50 / 50 / 0       | 7 / 14 / 16 ms            | なし                                                             | 9.4 回/秒・間隔 p95 151 ms                 |

- 連打の初回測定で、拒否された操作でも即時スナップショットを送っていたため大画面の受信が 17.9 回/秒に倍増していた → 確定イベントが
  出たときだけ即時送信するよう修正し、9.1 回/秒に戻ったことを再測定で確認。
- 30台試験の初回は DEMO GUEST の IP 単位上限（30回/分）で止まった。会場 Wi-Fi では全スマホが同じグローバル IP になるため、
  認証状態のポーリングと決済 API はブラウザごとの Cookie 単位の上限に変更（IP 単位は誤用防止の緩い上限のみ）。同じ IP の別ブラウザが
  締め出されないことをテストで固定（`lnurl.test.ts`）。
- 会場 Wi-Fi・実機スマホでの遅延は未測定。
