# 04 — Conference runbook / 会場運用手順（2026-10-30 時点）

実機リハーサル（会場 GPU・iPhone/Android・実ウォレット）の結果を反映して確定版にする。ここには今すぐ使える手順だけを書く。

## 機材

- 大画面 PC：GPU 付き（Chrome 最新）。1920×1080 出力。有線 LAN 推奨。
- サーバー：大画面 PC と同居でよい（Node 22.13+）。本番公開時は VPS + TLS（オーナー承認後）。
- 会場 Wi-Fi：来場者スマホが `PUBLIC_BASE_URL` に届くこと。
- 運営端末：ノート PC かタブレット（`/operator/`）。

## 起動（リハーサル・LAN）

```bash
pnpm install
```

```bash
pnpm build
```

```bash
OPERATOR_PASSWORD='12文字以上のパスワード' PUBLIC_BASE_URL='http://<大画面PCのLAN IP>:4400' WEB_MODE=static pnpm start
```

本番（インターネット公開）は `NODE_ENV=production`、https の `PUBLIC_BASE_URL`、`TRUST_PROXY=true`（リバースプロキシ配下）が必須。
公開・デプロイはオーナーの承認後に行う。

## 大画面（キオスク）

```bash
google-chrome --kiosk --autoplay-policy=no-user-gesture-required --noerrdialogs --disable-session-crashed-bubble "http://localhost:4400/display/"
```

- `--autoplay-policy=no-user-gesture-required` がない場合は、起動後に画面を1回クリック（右下に「クリックで音声有効化」が出る）。
- `F` キーでフルスクリーン。性能が足りない PC は `?q=BALANCED` または `?q=SAFE` を URL に付ける（運営の画質設定より低い方が使われる）。
- FPS が 28 未満の状態が約 9 秒続くと自動で画質を 1 段下げ、運営画面の DISPLAY 欄に実 FPS と画質が出る。
- WebGL コンテキストが失われたら「映像を復旧中」と表示し SAFE に下げて復帰を待つ。戻らなければページを再読み込み（試合は止まらない）。

## 1ラウンドの回し方（D-033：受付 → 出撃 → 戦闘2分 → 結果14秒）

1. 参加受付（LOBBY）：大画面に QR と「ボタンは3つだけ」の遊び方。来場者がスマホで読み取り「Lightningウォレットで認証」
   （LNURL-auth・無料）か、sandbox では「ウォレットなしで DEMO GUEST」→ **それで参加完了**（席選びなし・人数上限なし）。
2. 最初の1人から約30秒で自動出撃（運営画面「自動出撃」、混雑時プリセットは20秒）。待たずに始めるなら運営画面の一番上
   **「出撃する」**。運営画面は常に「今どの段階か」と「今押すべきボタン」と「押すと何が起きるか」を表示する。
3. 出撃演出 約8秒（「演出をスキップ」可）。
4. 戦闘 2分。NULL CORE の HP をゼロにすれば勝利。都市が3つ陥落・雷神の装甲 0・時間切れで敗北。途中参加OK（大画面右下に小さな QR）。
5. 結果 約14秒 → 自動で次の作戦。接続中のスマホはそのまま次の作戦に参加する。

混雑時は運営画面の試合の長さを `SHORT（戦闘 1分30秒）` に（受付中なら即反映、戦闘中なら次ラウンドから）。

### 係員の説明（30秒版）

「QR を読むと参加です。ボタンは3つ。**撃つ**でボスを削る、**守る**で攻撃予告の都市を守る、**直す**で雷神を直す。
迷ったら光っているボタンを押してください。横の **21 sats** は同じ行動の大きい版で、使わなくても勝てます。」

| ボタン | 無料タップ（1人 0.7 秒に1回） | 21 sats（任意・1人3回） | 大画面で起きること                                                         |
| ------ | ----------------------------- | ----------------------- | -------------------------------------------------------------------------- |
| 撃つ   | ボスの HP を少し削る          | 大きく削る              | 雷神の腕からビーム、ボスのバーが減る                                       |
| 守る   | シールドを貯める              | シールド +60            | 雷神の周りに青い盾。予告の都市に着弾する前に必要値まで貯めれば「守った！」 |
| 直す   | 装甲を少し戻す                | 装甲 +50                | 修理の緑の光。ボスの爪（3秒前に予告）で減った装甲が戻る                    |

### 展示デモ（スタッフ1人で回す）

運営画面 `DEMO BOTS` を ON：「DEMO-BOT 1〜6」が参加者として加わり、大画面の「今やること」どおりにタップする。ときどき VIRTUAL の
21 sats（DEMO 表示・お金は動かない）も見せる。自動出撃 ON なら、受付 → 出撃 → 戦闘 → 結果 → 次の作戦を無人で繰り返す。
来場者は BOT と一緒に遊べる（BOT は大画面・運営画面で BOT と表示され、「人」の人数には数えない）。説明が終わったら OFF に戻す。

## 運営ボタン

| ボタン                          | 使う場面                                                                         |
| ------------------------------- | -------------------------------------------------------------------------------- |
| PAUSE / RESUME                  | 機材トラブル・来場者の体調・説明が必要なとき。サーバーの試合時計が止まる         |
| END                             | 戦闘を打ち切って結果へ（確認ダイアログあり）                                     |
| NEXT ROUND                      | 結果表示を待たずに次へ                                                           |
| RESET                           | 何か変になったら。新しい試合（接続中のスマホはそのまま参加。確認ダイアログあり） |
| 自動出撃                        | 最初の1人から約30秒で自動で出撃（OFF なら「出撃する」を押すまで待つ）            |
| DEMO BOTS                       | 展示用 BOT 6体を参加させる（人と一緒に遊べる）                                   |
| HIDE CALLSIGNS                  | 全員のコールサインを隠して PILOT-XXXX 表示にする（不適切な名前への即時対応）     |
| SETTLE                          | sandbox の VIRTUAL 21 sats を確定（お金は動かない）                              |
| VIRTUAL を自動確定              | sandbox デモで VIRTUAL 21 sats を約1.5秒後に自動確定（SETTLE 係がいらない）      |
| RUN CHECKS / LIVE ON / LIVE OFF | 実決済の確認・開始・停止（下記。オーナー承認が前提）                             |
| MUTE                            | 会場アナウンス時に即ミュート                                                     |
| REDUCE FLASH                    | 光に敏感な来場者がいるとき（爆発・ビーム・リップルを弱め、カメラ揺れを止める）   |

すべての運営操作は監査ログ（画面下）と SQLite の `audit_log` に残る。

## 21 sats（大きい行動）

- 戦闘中いつでも、各ボタン横の「21 sats」から送れる（確認シートのあとで請求書）。効果は同じ行動の大きい版で、固定額。
  1人1試合3回・15秒に1回・1試合全体15回まで。誰が払ったかは大画面にもどこにも出ない（「Lightning 着金」とだけ出る）。
- 既定は sandbox：スマホで送る → 運営画面の sats 欄の `SETTLE` で確定（「VIRTUAL を自動確定」を ON にすると約1.5秒で自動）。お金は動かない。
- 支払いは任意。払わなくても最後まで遊べる・勝てることを口頭でも伝える。
- **実決済（LIVE）はオーナーの明示承認が前提**。手順は [`03_auth_and_payment.md`](03_auth_and_payment.md#live-化の手順オーナーの明示承認が前提)：
  環境変数を設定して起動 → `RUN CHECKS`（LNbits と公開 Webhook）→ 確認欄に `LIVE` → `LIVE ON`。止めるときは `LIVE OFF` の1クリック。
- 試合が終わってから入金が確認されたものは「unapplied」として運営画面と監査ログに残る。その場で来場者に説明し、返金などの対応は
  会場運営者のルールに従う。

## LNURL-auth の確認（リハーサル）

- ウォレットは https の公開ドメインにしか接続できない。`PUBLIC_BASE_URL` を公開 https にしてから実ウォレットで試す（公開はオーナー承認後）。
- 実ウォレットがない／LAN のリハーサルでは、スマホの「リンクをコピー」で得た `LNURL1...` をテスト用ウォレットで承認できる：

```bash
pnpm --filter @swed/server lnurl-wallet 'LNURL1...' 'rehearsal-wallet-1'
```

- 同じウォレットで2台目のスマホにログインすると、1台目は「別の端末からログインしたため降機」と表示され、参加は2台目に引き継がれる。

## トラブル時

| 症状                     | 対処                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| ------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| スマホが「再接続中」     | 電波を確認。45秒は参加者として数える。戻ればそのまま続けられる                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| スマホが QR から開けない | ①スマホで Safari を開き、大画面 QR の下の文字（例 `192.168.x.x:4400/pilot/`）を直接入力。開けば QR の読み取りの問題（iPhone の 設定 > カメラ > QRコードをスキャン を確認）。②開かなければ通信の問題：スマホがモバイル回線ではなく PC と同じ Wi-Fi か、ゲスト/公衆 Wi-Fi の「端末間通信の遮断」がないか、macOS の「node への受信接続」を許可したか。③PC の Wi-Fi のアドレス（Mac は `ipconfig getifaddr en0`）が QR と違えば `PUBLIC_BASE_URL=http://<そのアドレス>:4400` を付けて起動し直す（起動ログに他の候補も出る） |
| 大画面が「SIGNAL LOST」  | サーバー PC とネットワーク確認。ページは自動再接続                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| 大画面がカクつく         | 運営画面 QUALITY を BALANCED/SAFE、または大画面 URL に `?q=SAFE`                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| サーバー再起動が必要     | `Ctrl+C` → 再起動。試合は新しく始まる。パイロットの Cookie は残るのでページを開き直せば自動で参加                                                                                                                                                                                                                                                                                                                                                                                                                       |
| 起動しない               | エラーメッセージに不足している設定が出る（本番のパスワード/URL など）                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| ウォレットで認証できない | 期限切れ（5分）なら「もう一度」。非対応ウォレットなら sandbox の DEMO GUEST を案内                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| 実決済の確認が来ない     | 試合は止まらない。LNbits 障害なら `LIVE OFF` にしてデモ継続。後から確認できた分は運営画面に残る                                                                                                                                                                                                                                                                                                                                                                                                                         |
