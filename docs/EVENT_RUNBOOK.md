# EVENT_RUNBOOK — 会場運営ランブック（EARTH DEFENSE）

想定：カンファレンス会場の一角で大画面に投影し、**通りがかった人**が QR からスマホで搭乗する。8分のレイドが自動で繰り返すので、
スタッフが張り付かなくても回る。

> 本番デプロイ・外部公開・実決済はオーナーの明示承認後のみ。以下の「公開時」「実決済」は手順の準備であり、まだ実施していない。

## 機材

- 会場PC（WebGL対応GPU推奨）＋ プロジェクター/大型ディスプレイ（1920×1080 / 16:9 基準）＋ 音響（無音でも成立する）。
- ゲームサーバー（会場PCと兼用可）。会場Wi-Fi（参加者のスマホがサーバーに届くこと）。
- 予備：2D表示（`/arena?mode=2d`）、スポンサーパスの印刷束（ウォレットのない人・子ども向け）。

## 演出リハーサル

`/arena?preview=1` で演出だけを再生（サーバーには何も送らない）：
1 開幕 / 2 砲撃 / 3 シールド / 4 敵の予告 / 5 敵の攻撃 / 6 都市陥落 / 7 神雷風陣 / 8 成功 / 9 失敗 / 0 リセット。
通しリハーサルは `DEMO_MODE=true DEMO_BOTS=6` で8分間を最後まで（BOTは名前に BOT、決済に触れない）。

**デモシード（台本どおりの見本レイド、仕様 I1）**：DEMO_MODE の `/admin` → リハーサル →「デモシナリオ」→ ルート（成功／失敗）を選んで ▶。
待機中のレイドが台本つきのレイドに差し替わり、デモ機4体が決まった時刻に動く（0:30 札幌の予告と防衛、1:20 腕への命中、2:30 東京と大阪の同時危機、
3:20 送電、4:20 風神の修理、4:40 NULL CORE、6:50 神雷風陣のチャンス）。人は5人目として搭乗できる。成功ルートは神雷風陣で撃破、
失敗ルートは5:00以降だれも操作せず合体技が失敗して防衛失敗。同じ流れは `pnpm demo:seed` で事前に確認できる。
同じ画面の「敵を出す」「演出」ボタンで敵の出現や神雷風陣・勝敗の演出だけを会場画面で試せる（演出はゲームに作用しない）。

## 当日の起動（開場前チェック）

1. `pnpm start`（下の「起動方法」）。レイドは**自動でロビーを開き、自動で繰り返す**。
2. 会場PCで `/arena` を開き **F でフルスクリーン**、「クリックで音声ON」を押す。S で設定（品質・揺れ・点滅抑制・音量・2D）。
3. `/admin` にログイン →「監視」タブで会場画面の FPS が 30 以上か確認（低ければ品質「低」、または 2D）。
4. スマホで QR を読み、ゲストで搭乗 → 出撃パス（mockなら「テスト支払い」、FREEなら不要）→ 席を選ぶ → 出撃 →
   大画面に自分の結果が出ることを確認（名前を出す設定にしていなければ `PILOT-xxxxx`）。
5. スイッチ（新規決済・決済連携・搭乗受付・名前表示・自動ループ）がすべて意図どおりか確認。

## 回し方

- 基本は放置でよい：ロビー（60秒〜。最初の搭乗から20秒以上）→ 8分のレイド → 30秒の結果 → 次のロビー。
- 人が少ない時間は補佐AIが空いた席を手伝う（5人未満）。無人デモにしたいときは「デモBOT」（DEMO_MODE のみ）。
- 表彰・MCの時間などで止めたいときは「自動ループ」OFF（終了後に止まる）。即時に止めるなら「一時停止」。
- 「会場アナウンス」は定型文を優先（次の作戦・休憩・Wi-Fi・調整中・最終作戦）。自由入力は80文字まで、記号は除去される。

## トラブル対応

| 症状                          | 対応                                                                                                                                 |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| 不正・異常・会場トラブル      | `/admin` **🛑 緊急停止**（一時停止＋搭乗停止＋決済停止＋自動ループ停止）→ 原因確認 → 再開・各スイッチを戻す                          |
| 会場画面が重い/カクつく       | S → 品質「低」→ それでも重ければ描画「2D」。ゲームには影響しない                                                                     |
| 会場画面が真っ黒 / WebGL lost | 自動で2Dに切替。リロードで3D再試行                                                                                                   |
| 会場PCだけ回線断              | ゲームはサーバーで進行。再接続すると全量を取り直して追いつく                                                                         |
| サーバー再起動した            | レイドは PAUSED で復元される。`/admin` で再開。パス・経歴は失われない                                                                |
| スマホが繋がらない            | Wi-Fi確認。画面は自動再接続。Cookieが消えても同じ端末ならゲストが戻る（確実なのはLightningログイン）                                 |
| 「払ったのに乗れない」        | パス・決済タブの請求書 →「再照会」。締切後の入金は自動で「次の作戦のパス残高」。必要ならパイロット →「パス+1」（理由必須・監査ログ） |
| 決済プロバイダ障害            | 「決済連携」OFF（新規請求書の発行を止める）。スポンサーパスと既にパスを持つ人で続行                                                  |
| 不適切なコールサイン          | パイロット →「名前を隠す」（大画面では PILOT-番号）。全体は「名前表示」OFF                                                           |

## 終了後

- `/results/:raidId`、`/leaderboard` で記録を確認。`/admin` 監査ログ・パス集計を保存（会計用）。
- バックアップ：自動（レイド終了ごと・`BACKUP_INTERVAL_MINUTES` ごと、`BACKUP_KEEP` 世代）。会期終了時に `/admin`（owner）または
  `pnpm db:backup` で最終コピーを取り、`BACKUP_DIR` ごと別の場所へ保管。復元はサーバー停止中に `pnpm db:restore <ファイル>`。
- 支払いデータ（BOLT11）は24時間後に自動で消去される。アクセスログの保持期間はホスティング側で設定。

## 起動方法

```bash
pnpm install --frozen-lockfile
pnpm build                 # server: apps/server/dist/index.js、web: .next、solo: 単一HTML
cp .env.example .env       # 編集（下の表）
pnpm start                 # server(:4000) + web(:3000)
```

個別起動：`node --disable-warning=ExperimentalWarning apps/server/dist/index.js`、`pnpm --filter @sats-wars/web start`。

### 主な環境変数（全一覧は `.env.example`）

| 変数                     | 会場LAN（デモ）                     | 有料イベント（承認後）                     |
| ------------------------ | ----------------------------------- | ------------------------------------------ |
| `NODE_ENV`               | development                         | production                                 |
| `DEMO_MODE`              | true（無料・モックログイン・BOT可） | false                                      |
| `AUTH_MODE`              | mock（または both）                 | lnurl（本番は必須）                        |
| `PASS_MODE`              | FREE                                | PAID                                       |
| `PAYMENT_MODE`           | mock                                | lnbits ＋ `ALLOW_REAL_PAYMENTS=true`       |
| `SERVER_PUBLIC_URL`      | 空                                  | `https://api.…`（LNURL と Webhook に必須） |
| `ALLOWED_ORIGINS`        | 空（localhost/LAN を許可）          | `https://game.…`                           |
| `PUBLIC_PARTICIPANT_URL` | `http://<会場PCのIP>:3000/play`     | `https://game.…/play`                      |
| `EVENT_ID`               | local-demo                          | イベント名                                 |

### 会場LAN（インターネットなし）

会場PCで `pnpm start`。スマホは `http://<会場PCのIP>:3000/play`。Lightning ログインはウォレットからサーバーへ届く公開URLが要るので使えない
（ゲストのみ）。実決済は使わない。

### 公開時（HTTPS/WSS 必須、承認後）

詳細な環境差分・見積もり・スモークテスト・ロールバック・運営の確認項目は `docs/PRODUCTION_GUIDE.md`、合否は `docs/RELEASE_GATE.md`。

リバースプロキシ（Caddy / nginx）で TLS 終端：`https://game.example.com → web:3000`、`https://api.game.example.com → server:4000`
（WebSocket Upgrade を通す）。Web のビルド時に `NEXT_PUBLIC_GAME_SERVER_URL=https://api.game.example.com`。
サーバーは常駐プロセス（サーバーレスに載せない）、SQLite は永続ボリューム、単一インスタンス。

### 実決済（承認後）

1. LNbits のウォレットを用意し、**Invoice/read key** だけを `LNBITS_INVOICE_KEY` に（Admin key は使わない）。
2. `LNBITS_URL`、`LNBITS_WEBHOOK_SECRET`（長いランダム文字列）、`SERVER_PUBLIC_URL`（https）。
3. `PAYMENT_MODE=lnbits`、`ALLOW_REAL_PAYMENTS=true`。起動ログに実決済の警告が出ることを確認。
4. 少額で通し試験：請求書発行 → 実ウォレットで支払い → パス付与 → `/admin` の請求書が PAID → 監査ログ。
5. 締切後入金・Webhook 不達（ポーリングで回復）・決済連携OFF を試す。

### 監視

`/health`, `/ready`。`/admin` の「監視」（ソケット数、イベントループ遅延、tick遅延、メモリ、会場画面のFPS）、`GET /api/admin/metrics`。
ログは pino（JSON）、`LOG_LEVEL`。負荷の目安は `docs/LOAD_TEST_REPORT.md`。

### Docker

`Dockerfile` と `docker-compose.yml` は用意したが、このコンテナに Docker デーモンがなく**未検証**（D-062）。SQLite とバックアップは
ボリュームに置く。通常は `pnpm start` で足りる（外部DB不要、D-037）。
