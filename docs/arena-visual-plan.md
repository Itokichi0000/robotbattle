# 会場の大画面 `/arena` 映像品質：調査と実装方針（D-073）

評価基準は UI の綺麗さではなく、**大型スクリーンに映したときの 3D 映像の迫力と完成度**。
スマホの操縦 UI（D-072）は保持し、これ以上の作り込みはしない。通信・戦闘判定・Lightning 連携は変えない。

## 0. 方針（D-073）

- **大画面＝第三者視点の戦闘映像**：主役は雷神・風神の全身と NULL CORE。機体が実際に撃ち、守り、被弾する。
- **スマホ＝役割ごとのコックピット**（D-072 の PilotConsole をそのまま使う）。
- 2つを分けることで、会場の観客は「戦っている巨大ロボット」を、操縦者は「自分の席の計器」を見る。

## 2. 目指す画

- **舞台「東京湾 最終防衛線」**（オリジナル）：夜の湾岸に突き出した防衛プラットフォーム。手前に雷神と風神、海の上空に NULL CORE。
  地平線に**8都市の灯り**を並べ、予告はその灯りへのロックオンと光線、陥落は灯りが消える演出で見せる。
- **日本地図は 3D の主役から外す**：HUD の小さな作戦図（既存の 2D `TacticalMap`）に移す。従来の作戦卓は `?stage=table` で残す。
- **構図**：低めの第三者視点。機体の背中〜3/4 を手前に、ボスを奥に。機体が画面の高さの5〜7割を占めるカットを基本にし、全景は区切りだけ。
- **光**：月明かりの寒色キー、都市と海からの暖色の照り返し、機体の輪郭を切るリム、探照灯の光の筋、低く漂う霧。HDRI の映り込みで金属に見せる。
- **演出**：「溜め → 発射 → 着弾 → 反応」を機体とボスの体で見せる。群衆の操作ごとに寄らず、決めカットは間引く。

## 3. アセットの調達（併用する）

| ルート                 | 使い道                                                                                                                                                                                                        | 品質の見込み                                     | 承認                               |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------ | ---------------------------------- |
| A. Blender（今すぐ可） | このコンテナの bpy で雷神・NULL CORE を作り直す：ベベル・ブーリアンのパネル割り・細分割、法線/AO のベイク、塗装の剥げ・汚れを含む PBR テクスチャ（2K）。骨格・19 クリップ・検収はそのまま。目標 4〜8 万三角形 | 中〜高（硬い機械は得意。意匠の個性は人に劣る）   | 不要                               |
| B. AI 生成 GLB         | 画像→3D 生成（このセッションには Higgsfield の generate_3d が接続済み）。まず NULL CORE・護衛・背景の設備と建物群。人型の雷神・風神は部位ごと（頭・胸・肩・腕・脚）に生成して既存の骨格に組み付ける           | 形の情報量は高い。左右対称・UV・面の乱れは要修正 | **有料**・商用条件の確認           |
| C. CC0 素材            | HDRI（夜景・曇天）、金属と塗装の PBR テクスチャ。three.js リポジトリ同梱の Poly Haven 製 HDRI（`moonless_golf` など、CC0）は今の環境で取得できる                                                              | 高（光と質感が一段上がる）                       | 配布サイトはネットワーク許可が必要 |
| D. 人のアーティスト    | 最終の造形とアニメーション（`docs/art/ART_BRIEF.md` 済）                                                                                                                                                      | 最高                                             | 費用・期間                         |

**推奨**：A を主軸に着手し、C の HDRI を使う。B は NULL CORE と背景物で小さく試す（承認後）。D は並行して検討。

## 4. 実装の順番

1. **舞台と構図**：新しい舞台 `battlefield`（湾岸プラットフォーム・海・遠景の8都市・近い位置の NULL CORE）。地図は HUD の作戦図へ。旧の作戦卓は `?stage=table`。
2. **光とレンダリング**：HDRI の環境光、キー・リム・実用光の配置、影（機体の周囲に絞った 2048px のソフト影）、
   GTAO（three.js 同梱の後処理）で接地と隙間の陰、高さのある霧、光の筋（ボリューム風のコーン）、
   トーンマップ（ACES と AgX を比較）、カラーグレード、被写界深度は決めカットだけ。
3. **縦切り：雷神1体＋NULL CORE**：Blender で両者を作り直し、`/arena?stage=battlefield&preview=1` で
   「ボスの予告 → 雷神の肩砲 → 弱点に着弾 → ボスの反撃 → 雷神の被弾 → 神雷風陣」のループを完成させる。
4. **エフェクト**：銃口炎、ビーム（芯＋外光）、着弾の爆炎と煙（Blender で作る連番テクスチャ）、破片、六角のシールド面と波紋、
   熱のゆらぎ、ボス出現の裂け目と稲妻。
5. **カメラ**：第三者視点の基本カメラ（肩越し・低いアングル・ゆっくりした移動）、決めカット（発射・着弾・被弾・必殺・撃破）、カットの最短間隔。
6. **ゲーム状態との連動**：既存の演出キュー（任務の結果・敵の予告と攻撃・シールド・修理・ボスの部位の命中・神雷風陣の3分岐・勝敗）を
   新しい舞台につなぐ。勝敗はサーバー確定のまま、演出は再生するだけ。
7. **会場 HUD を最小限に**：上端の帯（WAVE・時間・CORE・SYNC・都市）、予告のコールアウト、必要な席、QR、作戦図。テレメトリーの退行を直す。
8. **展開**：風神と護衛、品質モード（High / Balanced / Low）。FPS は会場 GPU で実測する。

各段階で `/arena` を 1920×1080 で撮り、前の段階と並べて比べる（`pnpm ui:capture` と同じ方式）。

## 5. 守ること

- 通信・戦闘判定・Lightning 連携は変えない。スマホの UI は保持し、大きな再設計を再開しない。
- 箱型ロボを飾って完成としない。発光やブルームを増やして品質向上としない。
- 有料生成・素材の購入・ネットワーク設定の変更は、オーナーの承認後に行う。

## 6. 判断が必要なこと

1. 舞台の変更：地図を 3D の主役から外し、湾岸の戦場＋地平線の8都市にしてよいか。
2. AI 生成（Higgsfield）を使うか。使う場合の予算と、生成物の商用利用条件の確認。
3. CC0 素材サイトの許可：polyhaven.com・dl.polyhaven.org・ambientcg.com を環境の Allowed domains に追加するか
   （追加しなくても three.js 同梱の HDRI で始められる）。
4. 人のアーティストへの発注を並行して進めるか。
