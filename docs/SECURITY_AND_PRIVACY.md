# SECURITY_AND_PRIVACY

## 秘密情報

| 秘密 | 置き場所 | ブラウザ |
|---|---|---|
| `ADMIN_PASSWORD` | サーバー環境変数 | 運営が入力するのみ。アプリは配信しない |
| 管理セッショントークン | サーバーはSHA-256のみ（メモリ、12h） | sessionStorage |
| プレイヤートークン | サーバーはSHA-256のみ | localStorage（本人の残高を使う権限。同じ端末で再参加すると新トークンに置き換わり旧トークンは無効） |
| `LNBITS_INVOICE_KEY` | サーバー環境変数のみ | 渡さない（テストで確認） |
| `LNBITS_WEBHOOK_SECRET` | サーバー環境変数・LNbits設定 | 渡さない |
| 配布コード平文 | 発行時に1回だけ運営に表示 | 参加者が入力 |

`.env` は gitignore。`.env.example` はダミーのみ。本番は `ADMIN_PASSWORD`（12文字以上）と `ALLOWED_ORIGINS` が必須（未設定なら起動拒否）。

## 実装済みの対策

- 入力検証：全REST/Socket入力を Zod で検証。bodyLimit 32KB、Socket 16KB。
- 認可：プレイヤートークンで本人の請求書・残高・パンチのみ操作可。残高を使えるのは本人のトークンだけ。
- 管理：Bearer + Origin 許可リスト。全操作を監査ログ（パスワード・キー・平文コードは記録しない）。
- CSRF：Cookie を使わないため成立しにくい。加えて Origin 検査。
- レート制限（プレイヤートークン単位：会場NATで全員同一IPになる前提）、パンチは1人250ms間隔、応援は1秒間隔。
- 冪等性：パンチの `clientActionId`（DBの UNIQUE 制約）、請求書の加算・コードの消費（条件付きUPDATE）。
- 課金：着弾したパンチだけ残高から引く。残高は CHECK 制約で負にならない。運営の残高調整は理由必須で監査ログ。
- Webhook：秘密パス + 本文を信用せず再照会。存在有無を漏らさないため常に200。
- HTTPヘッダ：helmet（API）、Next の nosniff/Referrer-Policy/X-Frame-Options/Permissions-Policy。
- XSS：React のエスケープ。ニックネームは NFKC 正規化・制御/双方向文字除去・記号除去・12文字・URL風/不適切語の置換。運営が非表示可。
- 送金権限なし：アプリは送金APIを呼ばない。

## 個人データ

- 収集：任意ニックネーム、端末ID（ハッシュ）、プレイヤートークン（ハッシュ）、請求書データ、残高台帳。
- 収集しない：本名、連絡先、ウォレット識別子。IPはDBに保存しない（アクセスログは運用ポリシーで期間を決める）。
- 会場画面・公開スナップショットに支払い情報・残高・IP・トークンを出さない（ニックネームと集計のみ。誰がいくら払ったかは出ない）。
- BOLT11 は24時間後に削除。シーズンログ・台帳の保存期間はイベント後に運営が決める。
- 子どもの参加：保護者・運営方針に従う。無料の応援と配布コードの選択肢を常に維持。

## インシデント対応

1. `/admin` の **⛔ 緊急停止**：シーズン PAUSE + 新規チャージ受付停止 + 自動ループ停止（1クリック）。
2. 原因調査中もプレイヤーの残高は保持される。
3. キー漏えいが疑われる場合のローテーション：
   - `ADMIN_PASSWORD`：環境変数を変更して再起動（全管理セッション失効）。
   - `LNBITS_INVOICE_KEY`：LNbits で新キーを発行→環境変数更新→再起動→旧キー無効化。
   - `LNBITS_WEBHOOK_SECRET`：新しい値に変更（未処理の請求書はポーリングで回収される）。
4. 再起動したシーズンは PAUSED で復元（自動ループONなら10秒後に自動再開。調査が必要なら先に自動ループをOFF）。
