# ROADMAP — EARTH DEFENSE

フェーズは仕様書 H1 の実装順。現状は `docs/PROGRESS.md`、未完の詳細は `docs/OPEN_ISSUES.md`、公開前の合否は `docs/RELEASE_GATE.md`。

## 次の優先タスク（上から順に）

0. **会場の大画面 `/arena` の 3D 映像（D-073・D-074、最優先）**：舞台（東京湾 防衛線）・雷神と NULL CORE の作り直し・
   縦切りの通し（`/arena?preview=1` で B キー）は済。次は ① 最小限の会場 HUD（雷神に重ならない上端の帯） ② 風神を同じ手順で
   作り直す ③ 仕上げ（GTAO・決めカットの被写界深度・砲口の閃光・爆炎の連番・弱点ごとの着弾位置） ④ 護衛の作り直し。
   会場 GPU で FPS を測る。スマホの操縦 UI は保持し、追加の作り込みはしない（`docs/arena-visual-plan.md` §7）。
1. **会場リハーサル**（コードでは代替できない）：会場PC（GPU）・実Wi-Fi・iPhone/Android 数台で `docs/EVENT_RUNBOOK.md` の
   開場前チェックとデモシード（`/admin` → リハーサル → デモシナリオ）を通す。FPS・伝送遅延・タップ精度を記録し、
   `pnpm load:matrix` を会場ネットワークで再実行して `docs/LOAD_TEST_REPORT.md` に追記する。
2. **人間のプレイテスト**：難しさ・緊張感・席の分かりやすさ（OPEN_ISSUES のバランス項目）。必要なら難度プリセットと
   `difficultyDamageExponent`・`escortWing` を調整し、`pnpm simulate` / `pnpm sim:balance` で再確認、DECISION_LOG に記録。
3. **3Dモデルの仕上げ**：Blender のブロックアウト（全クリップ・ダメージ差分・アリーナあり）を人間のアーティストが造形し、
   会場GPUの FPS を測ってコード生成モデルと置き換えるか判断する（`tools/blender/`、`docs/ART_PIPELINE.md`）。
4. **承認後**：公開 HTTPS でのデプロイ（`docs/PRODUCTION_GUIDE.md`）、実ウォレットでの LNURL-auth、LNbits 少額試験。
5. 手動のアクセシビリティ確認（VoiceOver/TalkBack、キーボードのみ）と英語のネイティブチェック。
