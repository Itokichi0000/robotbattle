# UI 再設計の調査記録（ui-redesign-audit）— D-072

仕様：`SATS_WARS_CINEMATIC_UI_SPEC.md`（オーナー提供、v1.0）と、その前のオーナー依頼（コックピット HUD 化）。
目標：Web ダッシュボードではなく、巨大ロボットのコックピットに座っている感覚。3D の戦場が主、HUD は従。

## 実装技術（調査結果）

| 項目           | 実態                                                                                                   |
| -------------- | ------------------------------------------------------------------------------------------------------ |
| フレームワーク | web：Next.js 16（App Router）＋ Tailwind。体験版：Vite 相当の単一 HTML（React 19）                     |

### 保持するもの（ゲームロジック・通信）：変更しない

- **サーバーとの境界**：`RaidClient`（board / changeRole / requestTask / submitTask / gameNow）。
  - web は HTTP＋Cookie（`lib/raidClient.ts`）、体験版はブラウザ内エンジン（`LocalRaid`）。
  - クライアントは生入力だけを送る。
- **任務のライフサイクル**：要求 → 再開（リロード後）→ 時間切れ → 冪等な送信と再試行 → クールダウン → エラー表示。
  `Cockpit` の状態機械をそのまま移す。
- **表示用の算出**：`raidView`、`boardFrom`、`choiceOptions`（エンジンのおすすめ）、`effectSentence` / `resultSentence`。
- **ミニゲームの採点基準**：`useElapsed`、`reticleAt`、`gaugeAt`、ルーターのグラフ、整備の順番（入力形式は同一）。
- **web 側**：Socket.IO 接続（`useRaidConnection`）、ゲスト/Lightning 認証、出撃パス（`PassGate`）、
  応援 API、設定 PATCH、パスポート。体験版の `LocalRaid`（BOT・一時停止・次の作戦）。

## 変更する領域と危険箇所

- 変更：`packages/ui` の表示層（全面）、`apps/solo/src/App.tsx`（画面構成）、`apps/web/src/app/play/PlayApp.tsx`（画面構成）、
  `packages/three-game` の見た目（ロボの形状・材質・床・照明・ハンガー視点）。
- 触らない：エンジン・サーバー・プロトコル・`RaidClient`・認証・決済・`LocalRaid`。
- 危険箇所：
  - 任務の状態機械（再開・時間切れ・冪等送信）を移植するときの取りこぼし → 既存ロジックをそのまま移し、E2E で確認。
  - Space キーの二重発火（出撃と発射が同じキー）→ 状態ごとに一方だけ有効、キーリピート無視。
  - E2E がクラス名に依存 → `data-testid` / `data-*` 属性に置き換える。
  - HUD が 3D キャンバスのポインター操作を奪う → HUD 層は `pointer-events: none`、操作部だけ有効。

## 不明点・前提

- 満席・参加上限の概念はコードにない（`requiredDistinctPilots` は必殺技の条件）。席の「埋まり具合」は人数のみ表示する。
- 部位ごとの機体 HP はない（機体 HP・雷鼓/風環の損傷フラグのみ）。整備席の図は機体単位の状態だけを反映する。
- 一時停止はレイド全体の停止（運営操作／体験版のローカル）。個人の一時停止はない。

## Phase 2〜：設計方針

- 色（仕様 1.4 のトークン）：
  - `--sw-bg` #050A0F／`--sw-panel` #0A151D／`--sw-metal` #22313A／`--sw-line` #3A5260。
  - 文字は `--sw-text` #E1E9EE／`--sw-muted` #8BA5B4。
  - 意味の色：味方・正常・SYNC は `--sw-ally` #48C8D9、操作できるものは `--sw-action` #F5AE4F、
    敵・予兆・被弾は `--sw-danger` #F25F61、修復・成功は `--sw-success` #8FD3AA。
  - 面積の目安：暗部 80%、文字と構造 15%、強いアクセントは 5% 以下。
- 形：角丸なし。面取りした角、コーナーブラケット、細線、目盛り。
- 文字：Web フォントを増やさない。日本語ゴシック（既存）を主に使う。
  - 数値はすべて等幅（tabular-nums）。
  - 英語は計器の小さなラベルだけ（CORE INTEGRITY、TARGET LOCK など）。
- アイコン：絵文字を廃止し、専用 SVG（`packages/ui/src/hud/icons.tsx`）。
- 画面の流れ：パイロット認証 → ハンガー（ステーション選択・シミュレーター）→ 搭乗とコックピット起動 → 戦闘 HUD
  → デブリーフィング。
- 戦闘 HUD の配置（仕様 3.2）：
  - 上：テレメトリー帯（WAVE・残り時間・参加者・CORE・SYNC・予備電源・都市）。
  - 左上：作戦通信の直近1件（展開でログ）。右上：警告・予兆の直近1件。
  - 中央：3D 戦場と照準。左下に雷神、右下に風神の状態。下：担当席の操作 HUD。
  - 日本地図は 3D の戦術テーブル（体験版）／背景レイヤー（web のスマホ）。
- 演出：警告・ロックオン・被弾・発射・修理の短い遷移（2Hz 以下）。reduced motion ではすべて止める。
