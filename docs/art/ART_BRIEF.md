# 3D アセット発注仕様書 — SATS WARS: EARTH DEFENSE

3D アーティスト・アニメーター向けの発注仕様。ここに書いた名前・長さ・座標系を守れば、納品データはコードを変えずに
今の仮モデル（ブロックアウト）と入れ替わり、自動検査で合否が出る。デザインの背景は `docs/ART_PIPELINE.md`。

> 契約条件（金額・納期・権利）は運営が決める。§9 は相談のたたき台。

## 1. どこで使われるか

- 会場の大画面（1080p〜4K）にリアルタイム 3D で映す。ブラウザ上の three.js（WebGL）で描画する。
- 観客のスマホは操作画面なので 3D は出さない（体験版のみスマホでも 3D）。
- 勝敗はサーバーが決め、3D はその結果を演出として再生する。群衆が数秒ごとに操作するため、攻撃・被弾の動きは短く、
  途中で次の動きに上書きされることが多い。

## 3. デザインの決まり（必須）

- **完全オリジナル**。既存のアニメ・ゲーム・実在ロボット・商標を模倣・トレースしない。参考画像は雰囲気の共有まで。
- **ロボットに ₿ の記号を付けない**。Bitcoin 要素は「ブロックの積層」「鎖の結合」を装甲の意匠に抽象化する程度。
- 雷神と風神は**同じ側に並ぶ仲間**。敵は NULL CORE と Corruptor。
- 遠くからシルエットだけで判別できること（画面の高さの1割程度でも）：
  - 雷神：太く重い逆三角、厚い胸、巨大な拳、背面に雷鼓（太鼓と金の輪）。
  - 風神：細身、長い脚、背面に分割式の風環と刃状の翼。いつも少し浮いている。
  - 敵：墨黒と侵蝕赤。
- 配色（`docs/ART_PIPELINE.md` のパレット）：
  - 雷神：琥珀 `#F7931A`・黒鉄・銅・金。
  - 風神：青緑 `#25C8D7`・青紺・銀白。
  - 敵：墨黒・侵蝕赤 `#FF3B5C`・紫。
- **光るのは機能部分だけ**（雷鼓、風環、関節の光、ノード回路など）で、面積は小さく。
  会場画面には光のにじみ（ブルーム）があるので、大きな発光面はにじんで形が消える。
- 流血・人体表現なし。ダメージは**ひびと開いた装甲、そこから漏れる内部の機体色の光**で見せる（赤く塗らない）。

## 4. 技術仕様（ロボット共通）

| 項目         | 仕様                                                                                                                                       |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------ |
| 形式         | glTF 2.0 バイナリ（`.glb`）、Blender の標準 glTF 書き出し                                                                                  |
| 座標系       | 1 unit = 1 m、+Y が上、**前方 +Z**、ロボットの左 = +X。原点は足元の中央                                                                    |
| 大きさ       | 身長 約4 m（頭の高さ 3.5 m 以上、足 0.5 m 未満）                                                                                           |
| ポリゴン     | 1体 3万〜8万 三角形（**上限10万**、自動検査）                                                                                              |
| スキン       | 1体1スキン、ボーン 64 本以下                                                                                                               |
| マテリアル   | PBR（Metallic-Roughness）。テクスチャ 2K（2048px）まで：baseColor / ORM / normal / emissive。1体2セットまで。PNG か JPEG を GLB に埋め込む |
| 発光         | 発光させる材質は emissive に色を入れる（Blender の Emission Strength 1〜3 が目安）。ゲームが機体の電力に応じて明るさを上下させる           |
| 圧縮         | Draco・meshopt・KTX2 は**使わない**（下記）。軽量化はこちらで行う                                                                          |
| 背面ユニット | 雷鼓・風環は `BackUnit` という名前のノード（`Chest` の子）にまとめる。回転はクリップの中で付ける                                           |

**圧縮を使わない理由：** 今の読み込み処理が対応していない。また Draco は外部サイトからデコーダを読み込むため、
会場のセキュリティ設定（CSP）で止まる。

### スケルトン（ボーン名はこのとおり。ゲームが名前で探す）

```
Root ─ Hips ─ Spine ─ Chest ─ Neck ─ Head
                        ├─ UpperArm_L ─ Forearm_L ─ Hand_L
                        ├─ UpperArm_R ─ Forearm_R ─ Hand_R
                        └─ BackUnit
      Hips ─ Thigh_L ─ Shin_L ─ Foot_L
      Hips ─ Thigh_R ─ Shin_R ─ Foot_R
```

- 指などの追加ボーンは自由（合計64本まで）。
- **Root は動かさない（その場の動き）**。立ち位置と前進はゲームが管理する。
- 宙に浮く・沈む動き（風神の浮遊、着地のしゃがみ）は `Root` か `Hips` の上下で付けてよい。

### ダメージ段階

| 段階 | 機体HP  | 見た目                           | ノード名               |
| ---- | ------- | -------------------------------- | ---------------------- |
| 1    | 40〜69% | 胸のひびから機体色の内部光       | `damage1_*`（4つ以上） |
| 2    | 〜39%   | 胸板が浮いて光が漏れる、肩のひび | `damage2_*`（4つ以上） |

いずれも**既定で非表示**にする。ゲームが機体HPに応じて段階1→2と重ねて表示する。

## 5. アニメーション（雷神・風神）

**長さが大事：** ゲームはクリップの再生時刻を自分で進め、表の秒数が過ぎると待機（Idle）に戻す。
長いクリップは末尾が切れるので、**表の秒数以下（+0.1 秒まで）**で作る。30 fps 換算のフレーム数も併記する。

**ヒットマーカー：** 打撃が当たる瞬間（拳が伸び切る瞬間）。ゲームはこの時刻に、雷撃・火花・効果音・ヒットストップ
（ほんの一瞬の停止）を合わせる。表の秒数に合わせて作る。変えたい場合は秒数を知らせてもらえれば、
コードの `CLIP_HIT_TIME`（`packages/three-game/src/director.ts`）を1行直す。

| クリップ     | 秒   | 30fps | ループ | ヒット | 内容                                                                |
| ------------ | ---- | ----- | ------ | ------ | ------------------------------------------------------------------- |
| Idle         | 2.4  | 72    | ○      |        | 構え。呼吸と背面ユニットのゆっくりした回転                          |
| Intro        | 2.2  | 66    |        |        | 上空から着地（0.9 秒で接地）→ 決めポーズ                            |
| AttackLight  | 0.45 | 14    |        | 0.08   | 短い連打（ジャブ）。何度も上書きされる                              |
| AttackHeavy  | 0.6  | 18    |        | 0.33   | 溜めて大振り（雷神の主力）。0.33 秒で拳が伸び切る                   |
| Guard        | 0.8  | 24    |        |        | 腕で防御                                                            |
| HitReact     | 0.5  | 15    |        | 0      | 軽い被弾。最初のフレームで衝撃                                      |
| HitHeavy     | 0.9  | 27    |        | 0      | 重い被弾（ボスの攻撃）：のけぞり、片膝が落ち、立て直す              |
| Special      | 1.6  | 48    |        | 1.04   | 神雷風陣。雷神は両腕を掲げて叩きつけ（1.04 秒）、風神は旋回して突進 |
| Victory      | 2.0  | 60    | ○      |        | 勝利ポーズ                                                          |
| Defeat       | 1.4  | 42    |        |        | 膝をつく。最後の姿勢を保持する                                      |
| Walk         | 1.2  | 36    |        |        | その場で2歩（位置取り）。風神は軽く                                 |
| Dash         | 0.6  | 18    |        |        | 前へ短く踏み込んで戻る                                              |
| Hover        | 1.6  | 48    |        |        | 浮上（風神は高く、雷神は小さく跳ぶ）                                |
| ShieldDeploy | 0.9  | 27    |        |        | 風神が腕を開き、風環が都市の盾に展開                                |
| Charge       | 1.2  | 36    |        |        | 力を溜める：しゃがみ、腕を引き、背面ユニットが高速回転              |
| Boarding     | 2.4  | 72    |        |        | パイロット搭乗：片膝をつき、胸のハッチが光る → 立ち上がる           |

- 仕様書の名前 `Punch` `HeavyAttack` `HitLight` も同じ動きで**別名のアクションとして書き出す**
  （AttackLight / AttackHeavy / HitReact と同一）。合計19本。
- 必須の動き：雷神は Hover・ShieldDeploy、風神は AttackLight・AttackHeavy も、短い汎用の動きでよいので入れる
  （検査は16本＋別名3本すべてを見る）。
- 重さの原則：**溜め → 行き過ぎ → 収まり**。雷神は重く地面を踏みしめ、風神は軽く浮遊して慣性で流れる。
- 攻撃・被弾は途中で別の動きに切り替わっても破綻しないこと（極端なポーズで止めない）。

## 6. NULL CORE（ボス）

- 浮遊する巨大な球核、周囲に装甲片の輪、腕と脚にあたる独立部品。被弾すると装甲片が開き、内部の光が見える。
- 大きさと原点は Blender のブロックアウト（`assets/blender/null_core.blend`）に合わせる。ゲームは会場の奥の上空に置く。
- ボーン（名前で探す）：`Root` `Core` `Ring` `WP_CORE` `WP_ARM` `WP_LEG`。
- 弱点メッシュ：`weak_core` `weak_arm` `weak_leg`。それぞれ**専用の発光マテリアル**にする。
  ゲームが命中のたびに個別に明るくする。
- クリップ：

  | クリップ  | 秒  | 内容                                                           |
  | --------- | --- | -------------------------------------------------------------- |
  | Idle      | 3.0 | 浮遊（ループ）                                                 |
  | Telegraph | 1.2 | 攻撃の予告：コアがゆっくり脈打つ（ループ、点滅は1秒に1回以下） |
  | Attack    | 0.8 | 放射                                                           |
  | HitReact  | 0.4 | 被弾                                                           |
  | Defeat    | 2.0 | 崩壊                                                           |

- 現在ゲームで再生しているのは Idle と Telegraph。Attack・HitReact・Defeat は今後つなぐ予定なので、同じ名前で入れておく。
- 上限10万三角形（目安6万以下）。

## 8. 納品と検収

置き場所（`manifest.json` があれば会場画面が自動で使う。`/arena?models=auto`）：

```
apps/web/public/assets/robots/raijin.glb
apps/web/public/assets/robots/fujin.glb
apps/web/public/assets/robots/null_core.glb   （任意）
apps/web/public/assets/robots/arena.glb       （任意）
apps/web/public/assets/robots/manifest.json   {"RAIJIN":"raijin.glb","FUJIN":"fujin.glb","BOSS":"null_core.glb","ARENA":"arena.glb"}
```

自動検査（どちらも合格が条件）：

```bash
node tools/blender/inspect_glb.mjs apps/web/public/assets/robots/raijin.glb          # ボーン名・クリップ名・三角形数
node tools/blender/inspect_glb.mjs apps/web/public/assets/robots/null_core.glb --boss
pnpm --filter @sats-wars/three-game test   # 置いた GLB を three.js で読み込み、骨格・全クリップ・長さ・ダメージノード・
                                           # 身長と向き・ヒットマーカーで拳が前に出ていること を確かめる（glb.test.ts）
```

目視の確認：

1. `/arena?preview=1&models=auto` を開き、1〜9 キーで開幕・砲撃・シールド・都市陥落・神雷風陣・勝敗を再生する。
2. 遠くから見て雷神・風神・敵が形と色で判別できるか。
3. 光るのが機能部分だけで、にじみで形が消えていないか。
4. 打撃の瞬間に雷撃・音・停止が合っているか。
5. 会場PCで滑らかに動くか。高画質で 60fps が目標だが、**会場GPUでの性能はまだ測っていない**。重ければ三角形数とテクスチャを下げる。

**段階的な納品ができる：** 骨格さえ揃っていれば、足りないクリップはゲーム側の簡易モーションで代わりに動く。
次の順で区切ると、途中でもゲーム内で確認できる。

1. 三面図
2. ブロックアウト（大きさとシルエットをゲーム内で確認）
3. モデルとテクスチャ
4. リグと主要クリップ（Idle・AttackHeavy・ShieldDeploy・Special）
5. 全クリップ
6. 検収

途中段階のデータは「全クリップ」などの自動検査に落ちる。検収までに合格させる。
